# Upgrade AWF 1.8.9 to 1.9.0

Verify the new source/distribution pins, install the portable skill with its verified launcher, and use the existing adoption flow (`--mode install --on-conflict backup`) to prepare the project draft PR. Retain the previous skill backup, project configuration, operating pins and audit evidence. The owner merges governance changes; skill installation alone does not migrate a project. This is a minor release: Parts A and B of the change request add lifecycle events and change record schemas.

## Contracts and records

`ticket-contract` gains required `risk_tier`, `tier_justification`, `closure_standard`, `owner_closure_required`, `corrects`, `scope.evidence_paths`, `validation.required_resources` and `validation.platform_distinction`. Existing stored contracts must be re-issued with these fields (Tier 2, `FULL`, `false`, `null`, `[]`, `[]`, `null` are the conservative values); their `contract_hash` changes and downstream records rebind, as any contract change does. `worker-result`/`amendment-result` validation entries gain `tests_discovered`, `tests_executed`, `declared_skips` and `unevaluable_files`, plus a `closure` result; `critic-review` gains `closure`; findings gain `basis`, `supersedes_finding_id` and `path`, and a BLOCKER/MAJOR without a basis is refused. `ci-evidence.checks[]` gains `checkout_depth`; `run-attestation` and `host-lease` gain `resources_held`; `work-dispatch` gains `required_resources`; `final-gate` gains `local_ci_parity` (thirteen gates), `risk_tier`, `tier_justification` and `closure_standard`.

`jira-transition` gains `lifecycle_event` and required `read_back`; `merge_result_id` is nullable except for `JIRA_RECONCILED`. `controller-event.event_type` is now an enumeration including `evidence_comment` (requires `digest_sha256`) and `lifecycle_transition`. New owner-signed records: `review-cap-disposition`, `finding-disposition`, `tier-reassignment`, `owner-closure`; new `closeout-record`. The evidence bundle carries `finding_dispositions` and `cap_disposition`.

## Governance configuration

New keys in `.agentic/PROJECT_CONFIG.yaml`: `execution.risk_tiers`, `execution.max_cap_extensions` (default 2, maximum 3), `execution.host_broker.resources`, `validation.required_ci_checks[].verifies_history` and `local_command`, `jira.lifecycle_writes`, `jira.owner_closure_keywords`. Fresh bootstrap writes them; they are optional in the schema, so an upgraded 1.8.9 configuration stays ACCEPTED. Defaults for an upgraded configuration: no Tier 1 eligibility until `execution.risk_tiers` is set by a governance PR (fail closed), two cap extensions, all three lifecycle writes on (each still an EXPLICIT per-write prompt unless `controller.auto_transition_jira` is true), the documented owner-closure keyword list, and no named resources. `controller.auto_transition_jira` is now a boolean (default false). `jira.status_map.in_progress`/`in_review` are no longer reserved. A `PROJECT_INSTRUCTIONS.md` that contradicts the mandatory boundary rule is rejected by `validate-config`.

## Lifecycle

New states `REVIEW_CAP_REACHED` and `MERGED_PENDING_OWNER_CLOSURE` (both resumable); new events `CAP_REACHED`, `CAP_MERGE_WITH_NOTES`, `CAP_PARK`, `CAP_RESCOPE`, `CAP_EXTEND_ONE_CYCLE`, `OWNER_CLOSURE_REQUIRED`, control events `OWNER_CHANGES_REQUESTED` and `POST_MERGE_FINDING`. `AMENDMENT_ACCEPTED` additionally requires `amendment_cycles_available`; `JIRA_RECONCILED` additionally requires `closeout_valid` and either `owner_closure_not_required` or `owner_closure_verified`. `workflow.yaml` now carries `jira_writes`; installed copies are regenerated by adoption.

Jira policy supersedes 1.8.7 §B.1: the controller mirrors In Progress, In Review and Done as described in the [lifecycle](.agentic/docs/23-TICKET-LIFECYCLE.md). Projects that want the old single-write behaviour set `jira.lifecycle_writes.in_progress` and `in_review` to false.

## Host review loop

Host configurations accept optional `evidence_paths` and `max_cap_extensions`. Critic findings carry `basis` (`criterion:<id>` or `boundary:<CODE>`) and optional `supersedes`; enrolled `initial_findings` of BLOCKER/MAJOR severity need a basis before re-enrollment. At the cap the loop pauses with `REVIEW_CAP_REACHED` and `resume --disposition FILE` applies the owner's decision.

## Owner records

`finding-disposition`, `review-cap-disposition`, `tier-reassignment` and `owner-closure` are authenticated by `authorization.verify_owner_record`: the raw comment must render exactly from the record (`AWF1.2 DISPOSE kind=… record=… request=… decision=… subject=… head=… contract=… project=…`), its digest must match, the actor must be a trusted owner, and the producing run must be a registered `verifier` run independent of the worker and critic. An agent-produced record is refused. `CHANGELOG.md` entries before 1.8.5 were condensed to fit the documentation budget; the 1.6 archive keeps the full history.

## New commands and pilots

`workflow.py validate-closeout`, `digest`, `cap-plan` and `preflight`; `validate-record ticket-contract` checks tier eligibility against the project configuration. A review-policy pilot suite (`review-policy-cases.json`, six cases) and four routine cases (Jira lifecycle and closeout comment) are prepared; the routine preparation now yields four batches of three. No model pilot was run for this release; historical grades are unchanged.
