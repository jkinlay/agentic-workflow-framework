## Inline findings

### tools/canary/volume_bars.py:38

**[high] AC4 threshold validation is not enforced eagerly (generator body never runs unless consumed)** (blocking)

`volume_bars` is a generator function (it contains `yield`), so the body — including `if threshold <= 0: raise ValueError(...)` at tools/canary/volume_bars.py:38-39 — does not execute at call time. `volume_bars(ticks, threshold=0)` returns a generator object and raises nothing; the ValueError only surfaces when the caller iterates. AC4 says "A threshold of zero or less raises ValueError", and a caller that merely constructs the iterator (e.g. stores it, passes it around, or checks it in a guard clause) gets no error. The test at test_volume_bars.py:23-26 hides this because it wraps the call in `list(...)`. Fix: split into a thin non-generator wrapper that validates `threshold` (and returns the inner generator), e.g. `def volume_bars(ticks, threshold): if threshold <= 0: raise ValueError(...); return _volume_bars(ticks, threshold)`, and add a negative test that asserts `with self.assertRaises(ValueError): volume_bars([], threshold=0)` without list().

test_volume_bars.py:3 imports `from volume_bars import Tick, volume_bars` (implicit same-directory import, no package `__init__.py`, no relative import). The execution report claims the tests were run with `python -m unittest discover -s tools/canary` and passed 7/7; with `-s tools/canary` and no `-t`, unittest inserts the start directory on sys.path so it may work, but any other common invocation (`python -m unittest discover` from the repo root, `python -m pytest tools/canary`, or `python -m unittest discover -s tools/canary -t .`) will fail with ModuleNotFoundError. This makes the result environment-dependent and hard to reproduce in CI. ### tools/canary/volume_bars.py:56

**[low] float accumulation in vwap can drift for large buckets**

`_make_bar` computes `sum(tick.price * tick.size for ...) / volume` (tools/canary/volume_bars.py:56) using naive float summation. For large buckets or wide price ranges this accumulates rounding error; `math.fsum` (standard library, so within the constraint) gives an exactly-rounded sum at negligible cost. The single existing vwap test uses `assertAlmostEqual` on two prints, which cannot detect drift. Non-blocking, but worth fixing given this is priced market data.
