# Disposition of the 14 September review

This patch addresses the review of the 1.8.1 distribution. Prior release bytes and historical approval identities are preserved. The changes apply to any project; no customer-specific migration or external-engine activation is implied.

| Finding | Correction and evidence |
| --- | --- |
| P1: operator command omits regressions | Test fixtures load in both package and flat discovery. Archive acceptance executes actual `verify.py unit` from source extraction and installed project, requires passing fragments and equal counts. The ordinary record pipeline is also tested. |
| P2: socket timeout is not a wall deadline | Model phases run in supervised subprocesses with a 300-second wall deadline and bounded cleanup. Output cap is 8,000 tokens. One attempt per phase avoids overlapping retries when remote outcome/usage is unknown. Completed blind findings survive later failure. Real local child/loopback tests cover stalled and slow-drip responses, deadlines, redirection and error evidence. No generation-throughput calibration is claimed. |
| Unaudited reductions | Seeds, configuration reductions and increases are append-only ceiling events with project, revision, old/new values, time and provenance. Configuration reductions identify the admission request and policy hash. |
| Mutable ceiling table | Current authority derives from events. Transactional migration preserves legacy current values and seals the old table. Update/delete/REPLACE/UPSERT guards preserve recorded rows, including authorization/reconciliation audits. Database-owner access remains outside that integrity boundary. |
| Gate requires manual wake | A trusted `workflow_run` job verifies the producer, repository, PR/current head, workflow identity and source before rerunning only the matching trusted PR gate. Bounded attempts, skipped/draft runs and concurrent arrivals are covered by executable workflow tests. Actual GitHub deployment remains subject to server qualification. |
| Missing environment qualification | Secret-bearing required engines must include true `environment_secret_boundaries_verified` at the gate. Examples, component qualification and newly recorded local evidence retain false until actual verification. Copilot does not inherit an irrelevant secret environment requirement. |
| Smoke/benchmark residue | Public rubric visibility and prose now match distribution reality; compatibility filenames remain explained. A separate bounded actual-model evaluator accepts external pinned fresh cases/rubric, verifies current role-prompt bytes, records execution evidence and rejects tool/unknown events. Structured-decision grading remains distinct from executed project behavior or comparative prompt quality. Actual run outcomes are recorded separately in release evidence; unit tests do not count as model runs. |
| Approval expiry and sequencing | New grants bind expected value/revision and first-use expiry within 24 hours. Revision rejects stale approvals after an intervening change. Exact recorded requests replay read-only after expiry, including preserved legacy requests; new legacy-shaped grants fail. Migration documents staged policy and paused-admission sequencing. |
| Prompt evidence gaps | Critic prompts name required `file_manifest_sha256`; amendment prompt names `amendment-result`. All five generated prompts remain within 350 words and match templates exactly. |
| Late aggregate rejection | Incremental compact-JSON byte accounting rejects oversized metadata and accumulated files before reading further file contents. Existing per-file truncation stays explicit. |

The original work-folder status had already been corrected before this review arrived. Superseded build directories are retained under an explicit archival folder, while the validated distribution is copied to the shared distribution root. The release report identifies exact hashes and test results; builders alone do not claim validation.

The first Windows archive acceptance exhausted the 600-second source-test stage. That failed run is preserved. Per-test diagnostics showed slow real process fixtures and 23 policy-binding errors caused by stale generated offline examples after the patch-version change. The deterministic example generator corrected only the synthetic evidence bundle; prior release files and historical approvals were preserved. Acceptance now offers a bounded source/install timeout option and retains structured partial failure evidence. A longer window does not waive assertions or turn timed-out checks into passes.

Remaining external evidence: protected environment configuration, actual GitHub permission/provenance behavior and live disposable-canary qualification cannot be inferred from offline tests. A configured host must supply those observations before external-engine enablement. The bounded model evaluator measures responses to its particular cases; it does not authenticate provider identity or establish general prompt equivalence, autonomous execution or product ownership. No merge, Jira write or public release publication is performed by this patch.
