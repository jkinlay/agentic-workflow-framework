# Adopt AWF

In the first message explain that installing AWF changes repository governance files, so you will prepare a draft PR for the owner to merge. Missing default-branch rules are adoption warnings: continue installation, configuration mapping and PR preparation. Observe rules when access permits, report APPLIED/MISSING/UNOBSERVED, and offer `.agentic/templates/awf-main-ruleset.json`; its selector follows the actual default branch.

Inspect project instructions, accepted version, configuration, worktrees and owners. Preserve explicit version selectors. Verify catalogue/archive pins before running source. Compare owner releases and the bundled version; do not downgrade because a catalogue is old.

Read verified `.agentic/SPECIFICATION.md` and `.agentic/docs/20-NEW-PROJECT-SETUP.md`. Prepare isolated reviewed adoption, preserving project values and history. Move existing product-specific AGENTS instructions into reviewed project-owned `PROJECT_INSTRUCTIONS.md`; keep managed AGENTS byte-exact. Bootstrap defaults new `.github/CODEOWNERS` to `@maintainer`; use `--codeowner '@handle'` for another owner. Preserve existing project-owned CODEOWNERS. Fresh installation never needs an earlier release. Verified 1.8.3, 1.8.9, 1.9.1 and 1.9.2 installations upgrade directly to 1.9.3 with `--mode upgrade`; plan first with `--dry-run`.

Preserve real existing configuration; derivation fills new project values from observed target origin/metadata and supported test markers. Never invent repository IDs, owner IDs or successful tests. Bootstrap flags include `--github-repo OWNER/REPO`, `--repository-id NUMBER`, `--project-name NAME`, `--project-short-name SHORT`, `--test-command COMMAND` and paired `--jira-site HTTPS_ORIGIN --jira-key KEY`. New Jira defaults disabled with null site/key when neither is supplied; use local provisional records. An enabled Jira site without scope admits no Jira tickets or mutations. Preserve existing Jira mappings.

With exclusive ownership and quiescent adoption, bootstrap checks runtime imports and executes isolated installed `verify-installation` / `validate-config`. Inspect commands/exits/outputs. CONFIGURED needs both exit 0, integrity_valid=true/status=ACCEPTED and matching source/policy digests. `configuration` contains child-observed residue/warnings or UNOBSERVED; `pre_install_configuration` preserves earlier derivation. Unresolved configuration is INSTALLED_UNCONFIGURED; failed integrity is INSTALLATION_VERIFICATION_FAILED. Report exact paths/remedies. Unsafe imports produce NOT_RUN. Dry runs verify no installation. Empty CI/trusted-owner lists warn. `project_lint_scope` warns when Ruff/flake8 includes `.agentic`; add the reported project-owned exclusion.

Run installed `python -B -I ABS_INSTALLED_SCRIPT status`; copy its actual line/next action into `.agentic/templates/adoption-pr.md`. Status recomputes current shared checks, not historical child execution. INSTALLED means receipt-consistent bytes; CONFIGURED adds accepted adoption configuration. Neither independently authenticates release provenance. ACTIVE needs independent release trust through `--release-source ABS_SOURCE --expected-manifest-sha256 TRUSTED_PIN` (source outside the project) or the matching installed host AWF skill bundle, plus observed receipt-changing adoption merge and accepted raw managed/configuration/receipt/provenance bytes on the fresh default branch. Unrelated product edits may coexist. Receipt/branch/status assertions, skill replacement and PR preparation cannot establish acceptance; pins are not signatures. Unknown proof stays CONFIGURED with a concrete next action. ACTIVE never starts scheduling, qualifies engines or grants merge authority.

Live external review, scheduled amendments and agent pushes to repositories holding secrets require configured CI/actual trusted merge owners, observed repository rules and the selected mode's existing qualification. APPLIED baseline rules alone do not qualify an engine or configure required checks. Bootstrap never applies server rules. The owner may review/apply the template separately. Where the secret-repository push restriction applies, prepare the local branch and PR body for owner publication or observe rules first; otherwise open the draft through authorized host tools. Never import enablement conditions into a blanket refusal to adopt.

When adoption reaches CONFIGURED, show `workflow.py operating show` and offer: keep defaults, review Epics and recommend, or custom. Paste the table into the adoption PR. Read the verified `.agentic/docs/29-OPERATING-CONFIGURATION.md`: three streams default within a protected ceiling of six, one reviewer per stream. Preserve existing root `OPERATING_CONFIG.yaml`; its accepted hash must match actual installed validation. Direct user instructions may change choices within caps/allowlists/floors: translate, echo, run `operating set`, show results. Recommendations require acceptance; governance edits require a PR. Retain running reservations and drain surplus streams after reductions.

Validate the target and retain human governance/merge acceptance. An unavailable remote permits a local prepared change, never an invented PR.

## Routine ticket work

Read verified `.agentic/docs/23-TICKET-LIFECYCLE.md`. On COMPLETE, the assigned publisher pushes the feature branch/opens a draft. If worker Git-metadata writes are denied, it leaves the tested tree uncommitted with `commit_route: PUBLISHER`, `tested_tree`, `changes` and `ignored_untracked`; the publisher makes no content edits and requires `HEAD^{tree}` equality. Any difference returns to the worker as a scope violation. Observe PR/head, current validation and `draft_cleared` before critic review. READY_FOR_CRITIC precedes owner-ready and human merge authority. Publication still needs accepted bindings/live APPLIED rules and all scope, platform, secret and adapter prerequisites.

Jira lifecycle writes require existing explicit authorization and belong to the controller: WORKER_STARTED maps to `status_map.in_progress`; PR_READY to `in_review`; owner-requested changes or a review-head change to `in_progress`; post-merge JIRA_RECONCILED to `done` with its closing comment. BLOCK/PARK never write; never transition Epics. Read before/after. On mismatch/unknown outcome stop that ticket's writes, retain actor/time if observed (otherwise unknown), report suspected external automation conflict and never retry. Continue unaffected streams/read-only reconciliation. Selected `--codeowner` defaults new reviewer entries; verify actual access, independence and non-author eligibility separately. This documentation adds no eligibility enforcement.
