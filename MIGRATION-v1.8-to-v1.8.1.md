# Adopt the v1.8.1 correction

Skill installation and project adoption are separate. Preserve the accepted project baseline while preparing a scoped adoption change. Read [adoption](.agentic/docs/20-NEW-PROJECT-SETUP.md) and the applicable mode runbook; this guide supplements their commands.

1. Record the current release pins, active writers, installed files, project configuration, product instructions, scheduled enrollment and external-review settings. Back up the complete installation and protected routing ledger. Pause only affected writers/services; continue unrelated authorized streams.
2. Verify the new archive and manifest through the owner-controlled delivery channel, prepare a separate source cache and run the bootstrap dry-run. Cross-version adoption uses backed-up `install` mode, including this patch; same-version `upgrade` is maintenance only. Preserve real project values and evidence. Set the reviewed expected workflow version to `1.8.1`.
3. Before routing admission, confirm the intended retry cap against the previously accepted policy. The protected ledger now seeds its ceiling at the lower of 2 and that configured cap, retaining subsequent reductions. A higher previously configured cap cannot initialize a higher ceiling automatically. If a cap increase is explicitly authorized, the trusted host records the bound compare-and-swap operation described in [routing](.agentic/docs/27-MODEL-ROUTING.md). Neither the worker CLI nor an edited policy can approve it. Settlement and safe reconciliation remain possible while admission is blocked; preserve all charges and audit events.
4. Effective fingerprints normalize only omitted reconciliation defaults. Evidence reports the narrowly equivalent legacy hashes it includes; historical rows remain unchanged. Changed non-default caps, operators or other policy values stay separate. Retain original policy snapshots and do not treat representation equivalence as proof of model quality or authenticated outcomes.
5. Review [external-review setup](.agentic/docs/28-EXTERNAL-REVIEW.md). Keep it disabled until the actual project is qualified. Move each privileged credential to its dedicated protected environment, remove repository/organization copies, verify branch restrictions and trusted checkout guards, and retain existing required-engine policy. Map the inert example deliberately; do not install it over `.agentic/project.yaml`. Canary probes require separately provisioned external authorization material and can mutate their authorized disposable target.
6. Validate source/install integrity, project configuration, meaningful project tests and independent current-candidate review. Recheck environment/policy settings separately on the server before enabling external execution. Offline tests are not live qualification. Verify the accepted working checkout before reporting the patch active.

For rollback, stop affected execution and restore the recorded installation/configuration backup under human direction. Preserve newer ledger tables and audit records; never erase charges or reset the ceiling to recover capacity. Inspect compatibility before running an older router, which does not enforce the new ceiling. Reverify the original pins before resuming.
