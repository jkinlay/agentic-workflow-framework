Why use it

02 / 16

What AWF gives you

An unstructured coding chat

You coordinate every handoff

  • Requirements, changes and decisions accumulate in one conversation.
  • You repeatedly explain the scope and check what was tested.
  • A second opinion can become another untracked chat.
  • Several agents can edit the same files or duplicate work.
The same task under AWF

A repeatable delivery workflow

  • A reviewed specification becomes bounded tickets.
  • A controller assigns safe work to available lanes.
  • Writers implement. Independent critics challenge the candidate.
  • Tests and findings accompany a PR for your merge decision.
Use AWF for research tooling and software delivery. Research conclusions still need scientific validation.Source: User Guide · What AWF does

1.5 minutes. Explain the roles in everyday language: owner sets scope and decisions, controller coordinates, writer implements, critic independently reviews. AWF is neither a new IDE nor a standalone coding model. There is no promised throughput multiplier.

What’s new for the team

04 / 16

Practical highlights through 1.9.5

Before coding

Better project preparation

  • Specification and design review: turn an idea into measurable requirements, open decisions and an independently challenged design.
  • Jira planning: map the accepted specification to bounded tickets, dependencies and a safe delivery order.
  • Parallel lanes: the revised default policy configures 12 worker lanes A–L, with selectable approved model routes.
During delivery

Less manual coordination

  • Queueing and batching: order eligible PRs, validate integration and prepare separately reviewed batch candidates where supported.
  • Bounded independent review: risk tiers set review caps, with first-PASS stopping and explicit owner decisions at the cap.
  • Clearer evidence and recovery: record the writer, reviewer, candidate and uncertain external effects.
These are the current practical workflows and capabilities, including changes since the 1.8.9 deck.Source: User Guide · Key features

1 minutes. Do not imply that every feature originated solely in 1.9.5. The specification and Jira prompts are current documented operator workflows. They use the agent host’s supported tools and are not automatic shell commands. Capability in source, accepted operating policy and a qualified live host are distinct. Keep this caveat short in the room.

Two different mechanisms

Queue versus merge train

MechanismYour merge surface
Integration queueSource PRs remain the candidates. A disposable integration branch supplies validation.
Merge trainA new deterministic batch combines admitted PRs and gets its own reviews, CI, final gate and owner authorization.
Source approval only admits a PR to a batch. It does not approve the batch. Head or target drift requires fresh evidence.

Live batching needs a reviewed batch-capable adapter. The shipped reference controller adapter lacks those callbacks.

AWF retains human merge control for source and batch candidates. Queue and merge-train referenceSource: Queue and merge train

2 minutes. The practical benefit is fewer ad-hoc coordination decisions when several lanes finish. Dependencies come first. Do not claim auto-merge or working batch publication just from an enabled setting. Non-generated conflicts are refused rather than resolved by an unreviewed steward.
