# Disposition of the v1.8.2 review

This patch addresses the seven follow-ups in the 14 September review. The reviewed v1.8.2 source, distribution, historical approvals and failed model grade remain unchanged. The framework remains project-neutral.

| Finding | Correction and validation |
| --- | --- |
| Q1: one approval can be reused; expiry starts at call time | New increases consume stable approval and supporting evidence identities once across the canonical ledger. Migration indexes previously used references without changing legacy rows, even when historical references were duplicated. Exact recorded operations replay read-only. New requests include the source `approved_at`; first use requires `approved_at <= now < expires_at <= approved_at + 24 hours`. Value/revision comparison, reference consumption and the increase commit atomically. Tests cover reuse, cross-project/cross-field replay, concurrency, legacy preservation and stale times. The host still authenticates human direction, canonical source identity and approval time; timestamps and references are assertions, not cryptographic proof. |
| Q2: stale hashes appear as current review evidence | Final current-review records are checked individually against the exact verified release bytes. A fresh supplement cannot conceal a stale earlier claim. The final report requires coverage of every changed content file and retains per-file review attribution. Earlier review iterations stay separate historical records. Regressions reject post-review README/disposition edits, stale overrides, wrong release/scope, missing coverage and malformed paths/digests. |
| Q3: user-visible mojibake | The case-count error uses plain `1-12`. Hygiene detects narrow known Windows-1252 punctuation-corruption signatures and replacement characters, including in historical/test text; legitimate Unicode remains supported. This is a targeted corruption check, not a universal language detector. |
| Q4: wake-token scope and skipped producer jobs | Documentation states that `github.token` has broad `actions: write` capabilities. Wake checks the verified producer attempt's jobs and requires both the model and publisher to have completed successfully with matching identities. Skipped, failed, duplicate or mismatched jobs cannot consume the one automatic gate rerun. Existing trusted-source, PR/head, workflow and concurrency checks remain. |
| Q5: failed admission loses reduction audit | A validated lower configuration is observed under the admission write lock. A savepoint rolls back failed reservation work while retaining its reduction event. Events include an attempted run UUID and full request-context fingerprint; successful admission uses that UUID, while rejection creates no run or charge. Tests cover outstanding work, quarantine and budget/cost failures. Invalid configuration and abrupt process loss do not establish a committed observation. |
| Q6: transient provider failure recovery | Operations now explain that 429/5xx failures require coordinator recovery after reconciling outcome and usage, then a deliberate producer rerun. Unknown remote outcomes are not automatically retried. |
| Q7: Copilot nuance, endpoint policy and cleanup | Copilot ignores only the irrelevant environment-secret flag; all other required/supplied qualification flags retain literal-true checks. Parent and standalone child validate HTTPS endpoints and reject userinfo, query/fragment and malformed authorities. Explicit numeric-loopback HTTP is a local fixture opt-in; no workflow enables it. Stale imports/comments were removed. |

The portable channel guide also corrects family/exact-version examples. The release includes complete source and skill distributions, migration guidance and deterministic LF packaging. Acceptance executes the documented external-review command in fresh source and installed trees.

A separate twelve-case pilot uses new cases and a rubric fixed before responses, with explicit allowances for warranted precautions and clean controls. The [evaluation note](.agentic/benchmarks/native/EVALUATION-v1.8.3.md) records the protocol; observed execution status and any actual results are separate in the final validation JSON. Preparation is not execution. The original 1/3 FAIL is retained. A purposefully selected pilot does not establish statistical reliability, general prompt equivalence, provider identity or OS isolation.

Remaining external evidence: actual protected GitHub environments, App permissions, workflow provenance and disposable-canary behavior require a configured project and live qualification. No project migration, Jira write, merge, public release publication or ownership determination is performed by these local corrections.
