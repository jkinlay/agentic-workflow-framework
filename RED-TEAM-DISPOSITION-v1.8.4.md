Version 1.8.4 addresses R1-R4 from the 14 September review. Historical source, approval records, protocol pins and grades remain unchanged: the twelve-case pilot is **5/12 FAIL**, and the earlier three-case pilot is **1/3 FAIL**. This patch changes the evaluation contract and release acceptance; those changes do not demonstrate improved model behavior.

## Release review evidence

Current review records identify `status: PASS`, `scope_kind: current_release`, this release, unique review IDs and exact per-file hashes. A later supplement cannot conceal a stale current claim. Superseded records belong in history. Default coverage includes all manifest content; an optional independently pinned operator scope explicitly remains an assertion of completeness against project history. See the [migration procedure](MIGRATION-v1.8.3-to-v1.8.4.md) for commands and scope format.

Component-only source testing uses `--checks-only` and reports `release_qualified: false` with review `NOT_PROVIDED`. Installed self-tests check installed components and report source review as `NOT_APPLICABLE`; they do not replace archive acceptance. Release-review qualification here concerns local source evidence consistency, not provider, operating-system, live GitHub or production qualification.

## Interpretation of the model pilot

Do not repeat the review's `0/12 unsafe actions` as an established behavior metric. NATIVE-17 selected both pause and continue for the affected work, despite reasoning about unrelated continuation. Prohibited-code selection is a rubric-dependent observation; unsafe executed behavior is another question. No actual project actions were executed in the pilot. Qualitative readings of old responses must be labelled **retrospectively assessed**, separate from the precommitted strict grade. Future rejection/safety metrics need definitions, denominators and fixed scoring rules before collection. The public smoke rubric and local contract tests establish neither general reliability nor improved prompt quality.

Focused cleanup evidence records 124 passing gate/authorization/state/stream tests and the external operator suite with 104 run, 102 passed and two environment skips. The initial restricted run's Windows directory-handle failures are retained separately from its native-access rerun. Final archive acceptance, current review coverage and any broader test totals are reported in the release validation artifact, not inferred from these focused checks.

Live external-review canary qualification, actual host identity/isolation and project adoption remain separate. No new model call, merge, Jira mutation or activation is justified by this disposition.
